# Retry Policy

Network requests can fail transiently. gpui-query's `RetryPolicy` provides configurable automatic retries with exponential backoff and signal-checked cancellation.

## RetryPolicy

```rust
pub struct RetryPolicy {
    pub max_retries: u32,
    pub retry_delay: Duration,
    pub backoff_multiplier: f64,
    pub max_retry_delay: Duration,
}
```

| Field                | Type       | Default | Description                                  |
| -------------------- | ---------- | ------- | -------------------------------------------- |
| `max_retries`        | `u32`      | `3`     | Maximum number of retry attempts             |
| `retry_delay`        | `Duration` | `1s`    | Initial delay before first retry             |
| `backoff_multiplier` | `f64`      | `2.0`   | Multiplier applied to delay after each retry |
| `max_retry_delay`    | `Duration` | `30s`   | Upper bound on retry delay                   |

## Default Behavior

The default retry policy retries up to 3 times with exponential backoff:

```rust
let query = use_query(
    cx,
    QueryKey::from("user-profile"),
    |_| async move { fetch_user().await },
    QueryOptions {
        retry_policy: RetryPolicy::default(),
        ..Default::default()
    },
);
```

Retry timeline with defaults:

1. Initial fetch fails
2. Wait 1 second, retry (attempt 1)
3. Wait 2 seconds, retry (attempt 2)
4. Wait 4 seconds, retry (attempt 3)
5. Final failure, report error

## Custom Retry Configuration

### No Retries

```rust
RetryPolicy {
    max_retries: 0,
    retry_delay: Duration::ZERO,
    backoff_multiplier: 1.0,
    max_retry_delay: Duration::ZERO,
}
```

### Aggressive Retries

For critical data that must succeed:

```rust
RetryPolicy {
    max_retries: 10,
    retry_delay: Duration::from_millis(200),
    backoff_multiplier: 1.5,
    max_retry_delay: Duration::from_secs(5),
}
```

### Fixed Delay (No Backoff)

```rust
RetryPolicy {
    max_retries: 5,
    retry_delay: Duration::from_secs(2),
    backoff_multiplier: 1.0,
    max_retry_delay: Duration::from_secs(2),
}
```

## Exponential Backoff

The delay between retries follows this formula:

```
delay = min(retry_delay * backoff_multiplier^attempt, max_retry_delay)
```

Example with default settings (`retry_delay=1s`, `backoff_multiplier=2.0`, `max_retry_delay=30s`):

| Attempt | Delay | Calculation |
| ------- | ----- | ----------- |
| 1       | 1s    | 1 \* 2^0    |
| 2       | 2s    | 1 \* 2^1    |
| 3       | 4s    | 1 \* 2^2    |
| 4       | 8s    | 1 \* 2^3    |
| 5       | 16s   | 1 \* 2^4    |
| 6       | 30s   | min(32, 30) |

## Signal-Checked Retries

Retries are signal-aware. If the query is cancelled (e.g., component unmounts or key changes), the retry loop terminates immediately.

```rust
let query = use_query(
    cx,
    QueryKey::from("large-dataset"),
    |signal| async move {
        // The retry mechanism checks the signal between attempts
        // If cancelled, no further retries will be attempted
        if signal.is_cancelled() {
            return Err(QueryError::Cancelled);
        }
        fetch_large_dataset(signal).await
    },
    QueryOptions {
        retry_policy: RetryPolicy {
            max_retries: 5,
            retry_delay: Duration::from_secs(2),
            backoff_multiplier: 2.0,
            max_retry_delay: Duration::from_secs(30),
        },
        ..Default::default()
    },
);
```

<Callout type="info">
  Signal checking happens between retry attempts, not during the fetch itself. If you need to cancel
  within a long-running fetcher, check `signal.is_cancelled()` at strategic points in your async
  code.
</Callout>

## Retryable Errors

By default, all errors trigger retries. To customize which errors are retryable, check the error type in your fetcher:

```rust
let query = use_query(
    cx,
    QueryKey::from("api-data"),
    |signal| async move {
        let result = api_client.get("/data").signal(signal).await;
        match result {
            Ok(data) => Ok(data),
            Err(e) if e.is_timeout() || e.is_connection() => {
                // Transient errors - these will be retried
                Err(e)
            }
            Err(e) if e.is_auth() || e.is_not_found() => {
                // Non-retryable errors - return immediately
                Err(e)
            }
            Err(e) => Err(e),
        }
    },
    QueryOptions {
        retry_policy: RetryPolicy {
            max_retries: 3,
            ..Default::default()
        },
        ..Default::default()
    },
);
```

<Callout type="tip">
  Keep `max_retries` between 2 and 5 for most use cases. Too many retries can mask systemic issues
  and increase latency. Monitor retry rates to detect infrastructure problems.
</Callout>

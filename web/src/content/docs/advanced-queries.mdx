# Advanced Queries

Beyond the standard `use_query` hook, gpui-query provides specialized query variants for scenarios where you need more control over when and how data is fetched.

## use_query_manual

`use_query_manual` gives you full control over when the query executes. Unlike `use_query`, it does not automatically fetch on mount. You must explicitly trigger the fetch.

### Signature

```rust
pub fn use_query_manual<T, E>(
    cx: &mut ViewContext<impl 'static>,
    key: impl Into<QueryKey>,
    fetcher: impl Fn(QuerySignal) -> impl Future<Output = Result<T, E>> + 'static,
    options: QueryOptions,
) -> (QueryResource<T, E>, impl Fn())
```

### Usage

```rust
fn search_view(cx: &mut ViewContext<App>) {
    let (query, refetch) = use_query_manual(
        cx,
        QueryKey::from("search-results"),
        |signal| async move {
            let results = search_index.search(&search_term).await;
            Ok(results)
        },
        QueryOptions::default(),
    );

    // Fetch is NOT called on mount
    // Call refetch() to trigger it manually
    cx.render(move |_cx| {
        div()
            .child(
                button()
                    .on_click(|_event, cx| {
                        refetch();
                    })
                    .child("Search"),
            )
            .when_some(query.data(), |el, data| {
                el.children(data.iter().map(|r| div().child(&r.title)))
            })
    });
}
```

<Callout type="info">
  `use_query_manual` returns a tuple of `(QueryResource, refetch_fn)`. The refetch function can be
  called from event handlers or effects to trigger a fetch on demand.
</Callout>

## use_query_unsignalled

`use_query_unsignalled` is a lightweight variant that does not receive a `QuerySignal`. Use this for fetchers that do not need cancellation support and are fast enough that cancellation is unnecessary.

### Signature

```rust
pub fn use_query_unsignalled<T, E>(
    cx: &mut ViewContext<impl 'static>,
    key: impl Into<QueryKey>,
    fetcher: impl Fn() -> impl Future<Output = Result<T, E>> + 'static,
    options: QueryOptions,
) -> QueryResource<T, E>
```

### Usage

```rust
fn config_view(cx: &mut ViewContext<App>) {
    let config = use_query_unsignalled(
        cx,
        QueryKey::from("app-config"),
        || async move {
            // Simple, fast fetch - no cancellation needed
            let config = read_config_file().await?;
            Ok(config)
        },
        QueryOptions::default(),
    );
}
```

<Callout type="tip">
  Use `use_query_unsignalled` for fast, local operations like reading from a file or memory cache.
  For network requests or long computations, prefer `use_query` with signal support.
</Callout>

## fetch_query

`fetch_query` is an imperative function that fetches data outside of a component hook. Use it for one-time fetches, preloading, or non-reactive data access.

### Signature

```rust
pub async fn fetch_query<T, E>(
    client: &QueryClient,
    key: impl Into<QueryKey>,
    fetcher: impl Fn(QuerySignal) -> impl Future<Output = Result<T, E>>,
) -> Result<T, E>
```

### Usage

```rust
// Preload data before a view is mounted
async fn preload_user_data(client: &QueryClient) {
    let user = fetch_query(
        client,
        QueryKey::from("current-user"),
        |signal| async move {
            api::get_current_user().await
        },
    ).await;

    match user {
        Ok(data) => info!("Preloaded user: {}", data.name),
        Err(e) => warn!("Preload failed: {}", e),
    }
}
```

## fetch_query_with_signal

Like `fetch_query`, but accepts an externally created `QuerySignal`. This is useful for integrating with other cancellation systems or composing multiple async operations.

### Signature

```rust
pub async fn fetch_query_with_signal<T, E>(
    cx: &mut ViewContext<impl 'static>,
    client: &QueryClient,
    key: impl Into<QueryKey>,
    fetcher: impl Fn(QuerySignal) -> impl Future<Output = Result<T, E>>,
    signal: QuerySignal,
) -> Result<T, E>
```

### Usage

```rust
fn managed_fetch(cx: &mut ViewContext<App>, client: &QueryClient) {
    let signal = QuerySignal::new();

    // Use the signal in a fetch
    let result = cx.spawn(|mut cx| async move {
        fetch_query_with_signal(
            &mut cx,
            client,
            QueryKey::from("report"),
            |s| async move {
                generate_report().await
            },
            signal.clone(),
        ).await
    });
}
```

## When to Use Which

| Hook                      | Auto-fetch | Signal   | Use Case                              |
| ------------------------- | ---------- | -------- | ------------------------------------- |
| `use_query`               | Yes        | Yes      | Default for most data fetching        |
| `use_query_manual`        | No         | Yes      | Search, forms, user-triggered actions |
| `use_query_unsignalled`   | Yes        | No       | Fast local reads, config              |
| `fetch_query`             | N/A        | Yes      | One-time imperative fetches           |
| `fetch_query_with_signal` | N/A        | External | Composed async flows                  |

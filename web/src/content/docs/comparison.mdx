# Comparison with Alternatives

GPUI applications need async state management. Before gpui-query, developers had several options — each with tradeoffs. This guide compares gpui-query against the common alternatives.

## The Competitors

### 1. Manual `cx.spawn()`

The built-in GPUI approach. Spawn async tasks and manage state manually:

```rust
struct MyView {
    data: Option<Data>,
    loading: bool,
    error: Option<String>,
}

impl Render for MyView {
    fn render(&mut self, cx: &mut ViewContext<Self>) -> impl IntoElement {
        if self.loading {
            cx.spawn(|this, mut cx| async move {
                match fetch_data().await {
                    Ok(data) => this.update(&mut cx, |this, cx| {
                        this.data = Some(data);
                        this.loading = false;
                        cx.notify();
                    })?,
                    Err(e) => this.update(&mut cx, |this, cx| {
                        this.error = Some(e.to_string());
                        this.loading = false;
                        cx.notify();
                    })?,
                }
                Ok(())
            });
        }
        // render...
    }
}
```

### 2. gpui-query

Declarative queries with automatic caching, retry, and lifecycle management:

```rust
let query = use_query(cx, "my-data", || async {
    fetch_data().await
});
```

## Feature Comparison

| Feature                  | Manual spawn |     gpui-query      |
| ------------------------ | :----------: | :-----------------: |
| Caching                  |      ✗       |     ✓ Built-in      |
| Auto Retry               |      ✗       |   ✓ Configurable    |
| Request Deduplication    |      ✗       |     ✓ Automatic     |
| Cache Policies           |      ✗       | ✓ TTL, SWR, NoCache |

| Boilerplate              |     High     |       Minimal       |

## Code Comparison: A Real Feature

Let's implement "fetch user profile, show loading state, handle error, cache for 5 minutes."

### Manual `cx.spawn()` — ~40 lines

```rust
struct UserProfile {
    profile: Option<Profile>,
    loading: bool,
    error: Option<String>,
}

impl UserProfile {
    fn new(cx: &mut ViewContext<Self>) -> Self {
        let this = Self {
            profile: None,
            loading: true,
            error: None,
        };
        this.fetch(cx);
        this
    }

    fn fetch(&mut self, cx: &mut ViewContext<Self>) {
        self.loading = true;
        self.error = None;
        cx.notify();
        cx.spawn(|this, mut cx| async move {
            match fetch_profile().await {
                Ok(profile) => this.update(&mut cx, |this, cx| {
                    this.profile = Some(profile);
                    this.loading = false;
                    cx.notify();
                })?,
                Err(e) => this.update(&mut cx, |this, cx| {
                    this.error = Some(e.to_string());
                    this.loading = false;
                    cx.notify();
                })?,
            }
            Ok(())
        });
    }
}
// No caching. No retry. No deduplication.
```

### gpui-query — ~5 lines

```rust
let query = use_query(cx, "user-profile", || async {
    fetch_profile().await
}).with_cache_policy(CachePolicy::TTL(Duration::from_secs(300)));

// Automatic: caching, deduplication, loading state, error handling
// Bonus: retry, background refetch, diagnostics
```

## When to Use Each

### Use Manual `cx.spawn()` when:

- One-off async operations with no caching needs
- Fire-and-forget side effects (logging, analytics)
- Simple sequential operations that don't share state

### Use gpui-query when:

- Multiple components access the same async data
- You need caching, retry, or deduplication
- Background refresh improves your UX
- Pagination or infinite scroll patterns

### The Hybrid Approach

gpui-query and `cx.spawn()` coexist:

```rust
// Declarative data fetching — gpui-query
let users = use_query(cx, "users", || async { fetch_users().await });

// Imperative side effect — cx.spawn()
cx.spawn(|this, cx| async move {
    analytics.track("page_view").await;
    Ok(())
});
```

## Migration Path

Migrate incrementally from manual approaches:

1. Start with the highest-traffic query (file tree, user data)
2. Replace the manual fetch with `use_query`
3. Remove the manual state fields (loading, error, data)
4. Add cache policies for optimization
5. Repeat for the next query

Each migration is self-contained and doesn't affect other components.

## Summary

- **Manual `cx.spawn()`**: Maximum control, maximum boilerplate, no caching
- **gpui-query**: Purpose-built for GPUI async state — caching, retry, deduplication out of the box
- Use both together — gpui-query for data, `cx.spawn()` for imperative side effects

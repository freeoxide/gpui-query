# DevTools & Debugging

gpui-query provides built-in tools for inspecting and debugging query state. These utilities help you understand what is happening inside the cache at runtime.

## Dehydrate and Hydrate

### Dehydrate

Serialize the entire cache state into a portable format. This is useful for:

- Debugging the current state of all queries
- Transferring cache state between processes
- Persisting cache to disk for offline support

```rust
let client = cx.global::<QueryClient>();

// Serialize the full cache
let snapshot = client.dehydrate();

// Inspect the snapshot
for entry in &snapshot.entries {
    info!(
        "Key: {:?}, Status: {:?}, Age: {:?}",
        entry.key,
        entry.status,
        entry.updated_at.elapsed(),
    );
}
```

### Hydrate

Restore cache state from a previously dehydrated snapshot:

```rust
let client = QueryClient::new();

// Restore from a snapshot (e.g., loaded from disk)
client.hydrate(&snapshot);

// All queries are now available in cache
let resource = client.resource::<UserData, AppError>(
    QueryKey::from("user-profile"),
);
assert!(resource.data().is_some());
```

### SSR and Hydration

For server-side rendering scenarios, dehydrate on the server and hydrate on the client:

```rust
// Server side
let server_client = QueryClient::new();
// ... prefetch queries ...
let snapshot = server_client.dehydrate();
let json = serde_json::to_string(&snapshot)?;

// Client side
let client = QueryClient::new();
let snapshot: DehydratedState = serde_json::from_str(&json)?;
client.hydrate(&snapshot);
```

## ClientDiagnostic

`ClientDiagnostic` provides a read-only view of the client's internal state for debugging and monitoring.

### Accessing Diagnostics

```rust
let diagnostics = client.diagnostics();

info!("Total queries: {}", diagnostics.total_queries);
info!("Active queries: {}", diagnostics.active_queries);
info!("Cached queries: {}", diagnostics.cached_queries);
info!("Pending fetches: {}", diagnostics.pending_fetches);
```

### Diagnostic Fields

| Field             | Type    | Description                      |
| ----------------- | ------- | -------------------------------- |
| `total_queries`   | `usize` | Total queries in the cache       |
| `active_queries`  | `usize` | Queries with active subscribers  |
| `cached_queries`  | `usize` | Queries with cached data         |
| `pending_fetches` | `usize` | Currently in-flight fetches      |
| `stale_queries`   | `usize` | Queries with stale data          |
| `memory_usage`    | `usize` | Approximate memory used by cache |

### Query-Level Diagnostics

```rust
let query_diagnostic = client.query_diagnostic(
    &QueryKey::from("user-profile"),
);

if let Some(diag) = query_diagnostic {
    info!("Status: {:?}", diag.status);
    info!("Subscribers: {}", diag.subscriber_count);
    info!("Last updated: {:?}", diag.last_updated);
    info!("Fetch count: {}", diag.fetch_count);
    info!("Retry count: {}", diag.retry_count);
}
```

### Logging and Monitoring

Integrate diagnostics into your monitoring pipeline:

```rust
// Periodic diagnostics logging
cx.spawn(|mut cx| async move {
    loop {
        cx.background_executor().timer(Duration::from_secs(60)).await;
        let client = cx.read_global::<QueryClient>();
        let diag = client.diagnostics();

        if diag.pending_fetches > 100 {
            warn!("High pending fetch count: {}", diag.pending_fetches);
        }

        if diag.stale_queries > 50 {
            info!("Stale queries: {}", diag.stale_queries);
        }
    }
}).detach();
```

## Debug Utilities

### Dump Cache State

For development, dump the entire cache state to a readable format:

```rust
#[cfg(debug_assertions)]
fn debug_dump_cache(client: &QueryClient) {
    let diagnostics = client.diagnostics();
    println!("=== Query Cache Debug Dump ===");
    println!("Total queries: {}", diagnostics.total_queries);

    for entry in client.iter_queries() {
        println!(
            "  [{:?}] key={:?} status={:?} subscribers={}",
            entry.updated_at(),
            entry.key(),
            entry.status(),
            entry.subscriber_count(),
        );
    }
}
```

### Query Timeline

Track the lifecycle of a specific query:

```rust
let timeline = client.query_timeline(
    &QueryKey::from("user-profile"),
);

for event in &timeline.events {
    match event {
        TimelineEvent::Created(at) => println!("Created at {:?}", at),
        TimelineEvent::FetchStarted(at) => println!("Fetch started at {:?}", at),
        TimelineEvent::FetchCompleted(at) => println!("Fetch completed at {:?}", at),
        TimelineEvent::FetchFailed(at, err) => println!("Fetch failed at {:?}: {}", at, err),
        TimelineEvent::DataUpdated(at) => println!("Data updated at {:?}", at),
        TimelineEvent::Invalidated(at) => println!("Invalidated at {:?}", at),
    }
}
```

<Callout type="info">
  Diagnostic types are read-only snapshots. They do not hold locks on the client, so they are safe
  to log or send over channels without blocking query operations.
</Callout>

<Callout type="tip">
  Use `dehydrate` and `hydrate` for hot module reloading during development. Persist the cache
  before a reload and restore it after to avoid losing state.
</Callout>

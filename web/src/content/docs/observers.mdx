# Observers

Observers provide a low-level API for subscribing to query and mutation state changes. While hooks like `use_query` use observers internally, you can use them directly for advanced scenarios.

## QueryObserver

`QueryObserver` subscribes to a single query's state and invokes a callback whenever it changes.

### Creating an Observer

```rust
let observer = QueryObserver::<UserData, AppError>::new(
    &client,
    QueryKey::from(("users", user_id)),
);

// Subscribe to state changes
let unsubscribe = observer.subscribe(|resource| {
    info!("Query updated: status={:?}", resource.status());
    if let Some(data) = resource.data() {
        info!("Data: {:?}", data);
    }
});
```

### Manual Subscription Management

```rust
// Subscribe
let handle = observer.subscribe(|resource| {
    // React to state changes
});

// Unsubscribe when done
handle.unsubscribe();

// Or drop the handle to auto-unsubscribe
drop(handle);
```

### One-Time Fetch and Observe

```rust
let observer = QueryObserver::new(&client, key);
observer.fetch(|signal| async move {
    fetch_data(signal).await
});
```

## MutationObserver

`MutationObserver` subscribes to mutation state changes for a specific key.

### Creating a Mutation Observer

```rust
let observer = MutationObserver::<Todo, AppError, NewTodo>::new(
    &client,
    QueryKey::from("create-todo"),
);

let unsubscribe = observer.subscribe(|state| {
    match state.status() {
        MutationStatus::Idle => {}
        MutationStatus::Pending => {
            info!("Mutation in progress...");
        }
        MutationStatus::Success => {
            info!("Mutation succeeded!");
        }
        MutationStatus::Error => {
            warn!("Mutation failed: {:?}", state.error());
        }
    }
});
```

### Triggering a Mutation via Observer

```rust
observer.mutate(NewTodo {
    title: "Write documentation".to_string(),
    completed: false,
});
```

## InfiniteQueryObserver

`InfiniteQueryObserver` subscribes to an infinite query's state, tracking all pages and pagination status.

### Creating an Infinite Query Observer

```rust
let observer = InfiniteQueryObserver::<Vec<Item>, AppError>::new(
    &client,
    QueryKey::from("feed"),
);

let unsubscribe = observer.subscribe(|resource| {
    info!("Pages loaded: {}", resource.pages().len());
    info!("Has next page: {}", resource.has_next_page());

    let total_items: usize = resource
        .pages()
        .iter()
        .map(|p| p.len())
        .sum();
    info!("Total items: {}", total_items);
});
```

### Fetching Pages via Observer

```rust
// Fetch the first page
observer.fetch(|cursor, signal| async move {
    fetch_feed_page(cursor).await
});

// Load more pages
observer.fetch_next_page();
observer.fetch_previous_page();
```

## Observer vs Hooks

| Feature                | Hooks         | Observers   |
| ---------------------- | ------------- | ----------- |
| Reactive UI updates    | Automatic     | Manual      |
| Component lifecycle    | Tied to mount | Independent |
| Multiple subscribers   | One per hook  | Unlimited   |
| Use outside components | No            | Yes         |
| Memory management      | Automatic     | Manual      |

### When to Use Observers

- **Background sync services** that need to react to data changes without UI
- **Cross-component coordination** where multiple components need to know about state changes
- **Testing** where you need fine-grained control over subscriptions
- **Custom abstractions** built on top of gpui-query

<Callout type="info">
  Hooks are built on top of observers. If hooks satisfy your needs, prefer them. Observers are an
  escape hatch for advanced use cases.
</Callout>

<Callout type="warning">
  Remember to unsubscribe observers when they are no longer needed. Unsubscribed observers hold
  references to the client and prevent garbage collection of their queries.
</Callout>
